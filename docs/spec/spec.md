## 1. Overview

Sistema de agente de IA integrado ao WhatsApp que atua como assistente pessoal, recebendo mensagens de texto e audio em linguagem natural e executando acoes automatizadas: upload de arquivos no Google Drive, criacao/cancelamento de eventos no Google Calendar, agendamento de reunioes com Google Meet e envio de convites, e lembretes automaticos. _(Derivado de FR-1 a FR-8)_

### 1.1 Goals

- Receber e interpretar mensagens de texto e audio em portugues via WhatsApp _(FR-1, FR-2)_
- Upload automatico de arquivos para Google Drive com organizacao por tipo/data _(FR-3)_
- Criacao e cancelamento de eventos no Google Calendar via linguagem natural _(FR-4, FR-5)_
- Agendamento de reunioes com link Google Meet e envio de convites _(FR-6, FR-8)_
- Lembretes automaticos via WhatsApp antes de compromissos _(FR-7)_

### 1.2 Non-Goals

- Edicao de eventos existentes (apenas criar e cancelar na v1) _(CON-6, escopo v1)_
- Multi-tenant / multiplos usuarios simultaneos na v1 _(CON-6)_
- Lista pre-cadastrada de contatos (participantes informados na hora) _(ASM-6)_
- Integracao com outros calendarios alem do Google Calendar _(CON-3)_
- Interface grafica / dashboard web _(briefing: interface principal e WhatsApp)_
- Edicao/visualizacao de arquivos no Drive (apenas upload) _(briefing: escopo funcionalidade 1)_

### 3.3 Data Flow

**Fluxo 1: Mensagem de Texto** _(INT-2, FR-1, FR-4)_
```
1. WhatsApp webhook POST → extrair from + text.body
2. intent-classifier: GPT function calling → { intent, entities, confianca }
3. Se confianca < 0.7 → pedir clarificacao ao usuario
4. Rotear por intent → servico correspondente
5. Executar acao (ex: calendar.events.insert)
6. Enviar confirmacao via whatsapp.client
```

**Fluxo 2: Mensagem de Audio** _(INT-1, FR-2)_
```
1. WhatsApp webhook POST → extrair audio.id
2. whatsapp.client.downloadMedia(audioId) → Buffer OGG/Opus
3. audio-transcriber: ffmpeg Opus→MP3 → Whisper API → texto
4. Continuar como Fluxo 1 (texto)
```

**Fluxo 3: Arquivo + Comando** _(INT-1, FR-3)_
```
1. WhatsApp webhook POST → extrair document.id + text
2. Classificar intent como upload_arquivo
3. whatsapp.client.downloadMedia(docId) → Buffer
4. Classificar tipo do arquivo (mime_type)
5. drive.service: criar pasta se necessario → upload → confirmar
```

**Fluxo 4: Lembrete Automatico** _(INT-5, FR-7)_
```
1. Scheduler verifica a cada N minutos
2. Buscar eventos com remind_at <= agora AND not sent
3. Enviar lembrete via whatsapp.client
4. Marcar como enviado
```

### 3.4 Performance Strategy _(NFR-1: latencia < 30s)_

Para garantir resposta em < 30s end-to-end conforme NFR-1:

```
1. RESPOSTA IMEDIATA: Webhook responde HTTP 200 ao WhatsApp em < 100ms
   (processamento ocorre async apos o 200 OK — pattern do research.json)

2. FEEDBACK RAPIDO: Mensagem "Processando..." enviada ao usuario em < 2s
   (evita sensacao de "nada aconteceu" durante operacoes longas)

3. TIMEOUTS POR CAMADA:
   - WhatsApp Media Download: 10s timeout
   - Whisper API (transcricao): 15s timeout
   - OpenAI GPT (classificacao): 10s timeout
   - Google APIs (Drive/Calendar/Gmail): 10s timeout
   - Total pipeline maximo: ~25s (margem de 5s para NFR-1)

4. FALLBACK: Se timeout atingido em qualquer camada:
   - Notificar usuario com mensagem de erro descritiva (NFR-3)
   - Log estruturado do erro para diagnostico (via pino)
   - NAO enfileirar silenciosamente (NFR-3: zero operacoes perdidas)
```

_(Derivado de NFR-1, NFR-3, research.json: WhatsApp webhook pattern "respond 200 immediately")_
